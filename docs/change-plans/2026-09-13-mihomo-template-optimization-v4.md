## 2. 背景与目标

仓库目前用于管理可复用的代理配置模板。后续计划开发图形化配置生成软件，在开始软件开发前，先优化模板的跨平台说明、示例值、链式代理检查以及维护文档。

本轮目标：

- 保持 desktop 同时适用于 Windows 和 macOS。
- 保持 NAS 当前透明代理定位及已确认保留的网络行为。
- 统一必须由用户填写的示例信息，减少误用。
- 消除空字段、重复条目及不准确注释带来的维护问题。
- 在两套模板中增加住宅出口的完整链路自动健康检查。
- 补充可重复执行的手动验证流程、部署前提和缓存说明。

本轮不开展图形化软件开发，也不自动部署到用户电脑或 NAS。已明确不修改的项目不作为优化任务重新列入。不得借注释修正或清理扩大行为变更范围。

## 5. desktop 修改方案

### D1. Windows/macOS 共用端口配置

保留常规代理端口，将透明重定向端口改为注释示例：

```yaml
port: 7890
socks-port: 7891
mixed-port: 7892

# macOS/Linux TCP 透明重定向入口，需配套系统重定向规则。
# 常规 TUN 模式无需启用。
# redir-port: 7893

# 仅 Linux/Android 适用，Windows/macOS 不启用。
# tproxy-port: 7894
```

`redir-port` 可用于 macOS，但不属于 Windows/macOS 共用的默认入口。仅开启监听不会自动建立系统重定向规则。README 应说明：macOS 若实际使用 redir，需自行启用并配置相应转发规则。

这两个端口都不是 TUN 所必需。保留 7890、7891、7892，避免改变已有显式代理应用的端口设置。[官方代理端口说明](https://wiki.metacubex.one/config/inbound/port/)

### D3. 保留进程识别并修正注释

```yaml
# 尝试识别本机连接所属进程，供连接信息展示和进程规则使用。
# 实际识别结果取决于系统、权限与连接类型；本项不会自动添加进程分流规则。
find-process-mode: always
```

删除“供后面的 Edge 专用规则使用”的过时说明。保留用户需要的强制进程识别行为，不改为 `strict` 或 `off`。

README 简要说明：进程识别可辅助连接排查和进程规则，但不能保证每条连接都识别成功，Windows/macOS 的进程名称与路径也可能不同。

### D4. 调整 UDP 空闲超时

```yaml
udp-timeout: 300  # UDP NAT 映射空闲过期时间，单位：秒
```

将原 3000 秒缩短为 300 秒。该项描述空闲映射过期，不表示所有 UDP 连接运行五分钟后都必须断开。同步更新 README 示例。[官方 TUN 参数说明](https://wiki.metacubex.one/config/inbound/tun/)

## 6. NAS 修改方案

### N1. 统一住宅节点示例值

```yaml
server: socks5.example.com
port: 1080
username: "YOUR_SOCKS5_USERNAME"
password: "YOUR_SOCKS5_PASSWORD"
```

替换含义不明的 `server: server`、`port: port` 等示例。端口必须保持整数，不能以字符串提示代替。说明这些字段需要在实际部署配置中填写；类型正确不代表示例节点可以连接。

### N2. 控制密钥使用明确占位符

```yaml
# 部署前替换为独立随机密钥，并在管理面板中填写相同值。
secret: "CHANGE_ME_CONTROLLER_SECRET"
```

移除公开固定密钥，增加部署填写说明。占位符不是自动生成机制，用户必须自行替换。此项不调整控制接口监听方式。

### N3. 入站示例账号精简为一组

```yaml
# 其他设备连接 NAS 的 HTTP/SOCKS/mixed 代理端口时使用。
# 与住宅代理账号、控制接口 secret 相互独立。
authentication:
  - "CHANGE_ME_PROXY_USER:CHANGE_ME_PROXY_PASSWORD"
```

仅将六组示例账号改为一组。README 说明部署前替换，如需多用户可追加。此项不调整允许来源网段和免认证前缀。

明确三个凭据用途：

| 凭据 | 使用方向 |
| --- | --- |
| NAS 入站账号 | 其他设备连接 NAS 的代理端口 |
| 住宅代理账号 | Mihomo 连接住宅代理服务 |
| 控制接口密钥 | 管理面板连接 Mihomo API |

### N5. 保留透明代理设置，补充部署前提

保留现有 TUN、自动路由、自动重定向、严格路由等设置，仅改进说明。

**显式代理**：应用主动连接代理端口，例如 NAS 的 7892。未遵循代理设置的应用不一定进入 Mihomo。

**透明代理**：应用正常发起连接，系统路由、TUN 或重定向机制把符合条件的流量交给 Mihomo，再由规则决定直连或代理。“透明”不代表所有流量都使用住宅出口。

README 至少区分以下场景：

| 场景 | 部署要点 |
| --- | --- |
| 仅提供 7892 显式代理 | 客户端填写 NAS 地址、端口及入站凭据；通常无需 TUN |
| 接管 NAS 本机流量 | TUN 支持、权限及正确的网络命名空间 |
| 接管其他设备流量 | 客户端流量实际经过 NAS，具备转发及正确的回程路径 |

说明 Docker 的网络模式、必要网络权限及 TUN 设备访问条件。不能把“容器中开启 TUN”描述为自动接管宿主机或整个局域网。提供仅使用显式代理时按需关闭 TUN 的指引，不修改模板当前默认定位。

### N6. 补充 IPv6 路由排除

在现有 `tun.route-exclude-address` 列表末尾追加，保留已有 IPv4 条目：

```yaml
# IPv6 本机回环
- ::1/128
# IPv6 唯一本地地址（ULA）
- fc00::/7
# IPv6 链路本地地址
- fe80::/10
# IPv6 组播
- ff00::/8
```

保持现有 IPv6 开关。上述目的地址遵循系统原有路由；路由排除不是防火墙放行规则。

README 说明局域网也可能使用运营商全球 IPv6 前缀，应按真实网络判断是否追加，不能排除整个公网 IPv6 范围。实施后检查实际路由、本机和局域网服务访问，不能只凭 YAML 判定接管正常。

### N7. 三个协议级目标覆盖设为 false

保留全局 `sniffer.override-destination: false`，将 HTTP、TLS、QUIC 各自的 `override-destination` 从 `true` 改为 `false`。

```yaml
sniffer:
  override-destination: false
  sniff:
    HTTP:
      # 保留原有 ports
      override-destination: false
    TLS:
      # 保留原有 ports
      override-destination: false
    QUIC:
      # 保留原有 ports
      override-destination: false
```

实际修改时保留完整的端口及其他嗅探设置。该变更让连接保留原始目标，嗅探仍可辅助规则判断；同步改正三处建议开启覆盖的旧注释。[官方嗅探说明](https://wiki.metacubex.one/config/sniff/)

### N9. 注释固定 MTU

```yaml
# mtu: 3000  # 按实际网络测试后设置；未指定时使用当前内核默认值
```

不另行指定新值，也不声称某个固定 MTU 一定带来更高速度。

## 7. 两套模板的共通修改

### C1. 本地 DNS 示例及填写要求

保留当前 DNS 总体结构，明确 `192.168.50.1` 是示例地址。

- 在模板顶部加入部署前检查：填写目标部署网络中能解析内网名称的实际 DNS。
- 不使用配置生成软件所在电脑的 DNS 代替 NAS 所在网络的 DNS。
- 提醒上游不能回指 Mihomo 自己而形成循环。
- 提供 `+.lan`、`+.home.arpa` 等按需启用的注释示例。
- 区分普通 DNS 和 `.local` 常涉及的 mDNS 设备发现，不能承诺增加普通 DNS 策略就能解决所有发现问题。
- 不猜测真实路由器地址，不在有效地址字段写入未经处理的变量。

### C3. 注释空 fallback-filter

```yaml
# fallback-filter:  # 需要自定义 fallback 筛选条件时再配置
```

保留现有 fallback 上游，修正“仅在主 DNS 无响应时使用”的说明。省略自定义字段不等于禁用内核默认筛选行为。[官方 DNS 说明](https://wiki.metacubex.one/config/dns/)

### C4. 整理 Fake-IP 例外

- 删除 NAS 完全重复的 `+.nas`、`+.time.edu.cn` 等条目。
- 对被更广条目覆盖的项，先核实通配语义，仅在确实等价时合并。
- desktop 补充本地域名例外，例如 `localhost`、`+.local`、`+.home.arpa`，并解释用途。
- 不大范围删除音乐、游戏和 STUN 兼容项。
- 实施记录列出具体增删项，便于追踪变化。

Fake-IP 例外影响真实地址与虚拟地址的返回，不会自动决定直连，也不能单独证明 WebRTC 或 UDP 行为符合预期。

### C5. 规范空字段

三个只通过 `use` 引入订阅的入口组，将无内容的 `proxies:` 改为：

```yaml
proxies: []
```

NAS 暂未使用的可选字段整体注释，示例：

```yaml
# force-domain:
#   - "+.example.com"

# skip-src-address:
#   - 192.168.50.100/32
```

保留已有非空列表。`fallback-filter` 属于映射字段，按 C3 处理，不改为 `[]`。

### C6. 六订阅使用说明

保留六个 provider 和当前引用结构。在模板顶部、订阅段及 README 中说明：

> 默认启用六个订阅。请填写全部已启用订阅；若停用某个订阅，应同时停用对应 provider，以及 `Manually Select Nodes`、`Auto Select Nodes`、`Fallback` 中对应的 `use` 引用。

说明只改 URL、只删除 provider 或只删除组引用分别可能留下的未配置项，帮助手动维护用户保持一致。

### C8. 住宅出口自动健康检查

#### C8.1 添加位置与完整代理组片段

在两套模板现有的 `chain-hop2-exit` 中增加五个健康检查字段，采用相同值：

```yaml
- name: chain-hop2-exit
  type: select
  proxies:
    - USA_Static_Native_ISP

  # 检查完整链路：当前入口节点 → 住宅出口 → 测试网站。
  # 住宅节点必须保留 dialer-proxy: chain-hop1-entry。
  url: https://www.gstatic.com/generate_204
  interval: 600
  timeout: 10000
  lazy: false
  expected-status: 204
```

此片段是 `proxy-groups` 下现有组的修改结果，不创建第二个同名组。字段直接写在代理组内，不使用订阅 provider 的嵌套 `health-check:` 写法。

#### C8.2 参数与预期行为

| 参数 | 值 | 目的 |
| --- | --- | --- |
| `type` | `select` | 保留现有出口选择机制 |
| `proxies` | 现有住宅节点 | 明确检查对象 |
| `url` | 现有 Google 204 地址 | 与模板已有测试地址一致 |
| `interval` | `600` 秒 | 每十分钟定期检查 |
| `timeout` | `10000` 毫秒 | 为两跳连接预留十秒 |
| `lazy` | `false` | 出口组空闲时仍定期检查 |
| `expected-status` | `204` | 将符合预期响应的检查视为成功 |

第四版明确采用 `lazy: false`，取代早期可选示意中的 `true`。代理组通用健康检查可以用于直接列在 `proxies` 中的节点。[官方代理组配置](https://wiki.metacubex.one/config/proxy-groups/)

定期检查会产生少量入口和住宅服务流量。内核停止、设备休眠或网络断开期间无法正常完成；本功能不包含系统通知或后台独立监控服务。

#### C8.3 检查链路

住宅节点必须保留：

```yaml
dialer-proxy: chain-hop1-entry
```

实际健康检查业务连接：

```text
运行 Mihomo 的电脑或 NAS
    ↓
chain-hop1-entry 当前选中的第 1 跳入口
    ↓
USA_Static_Native_ISP 第 2 跳住宅代理
    ↓
健康检查网站
```

健康检查不会为测速而自动忽略住宅节点的 `dialer-proxy`。入口选择手动、自动选择或回退组时，检查使用该组当时选中的节点。[官方链式代理说明](https://wiki.metacubex.one/config/proxies/dialer-proxy/)

| 检查对象 | 路径 |
| --- | --- |
| 订阅入口节点 | Mihomo → 入口 → 测试网站 |
| 保留上述 dialer-proxy 的住宅节点 | Mihomo → 当前入口 → 住宅出口 → 测试网站 |
| 外部工具的住宅端口探测 | 由工具网络路径决定，不能替代完整链路检查 |

不会遍历所有入口与住宅出口组合。入口切换后历史结果可能仍对应旧入口，应重新测试。节点域名解析、订阅下载等辅助请求仍遵循各自配置，不能据此推断也全部经过住宅出口。

#### C8.4 结果边界与故障行为

成功表示当次请求经当前链路访问测试地址并取得预期响应，不证明出口 IP 属性、所有网站、UDP 或实际业务均正常。

失败可能来自入口、住宅认证、服务可达性、DNS、超时或测试网站。应结合错误和手动验证定位，不能直接断定住宅服务器故障。

保留 `select`，不增加绕过住宅的回退选项，不自动遍历入口、不保证自动修复。用户选择的入口组仍按原有逻辑运行。状态展示方式取决于客户端或管理面板。

#### C8.5 文档与验证

两份 README 增加自动检查的参数、路径、结果解释与诊断步骤，同时保留第 8 节手动验证流程。

自动健康检查验收：

1. 两份配置能被目标版本加载，引用正确。
2. 固定入口、填写有效住宅信息，能取得正常结果。
3. 不主动使用住宅出口时仍可观察到定期结果更新。
4. 在独立测试配置中使用错误凭据，检查失败且不绕过住宅出口。
5. 恢复正确信息后，结果能够恢复。
6. 更换入口后重新检查，测试请求使用新入口。
7. 用实际出口查询及业务测试补充验证。

### C9. 首次启动、资源下载与缓存

## 8. 住宅链路手动验证流程

### 8.1 准备实际配置副本

在私密部署副本中填写订阅、住宅信息和 NAS 所需凭据，不写回公共模板。加载后检查解析和引用错误，更新订阅，记录当前模式和策略选择。

### 8.2 固定第 1 跳

将 `chain-hop1-entry` 选为 `Manually Select Nodes`，再选具体入口 A。测试入口延迟，避免自动切换使结果无法归因。

入口成功仅说明入口能访问对应测试地址。

### 8.3 检查住宅完整链路

使用客户端基于 Mihomo 内核的节点延迟测试检查 `USA_Static_Native_ISP`。由于住宅节点保留 `dialer-proxy`，请求会经过入口 A 和住宅出口。

记录结果、超时或认证错误。延迟包含连接建立和请求过程，不能简单解释为两跳网络延迟相加。

### 8.4 验证实际出口 IP

为避免查询网站命中其他规则，在可中断的测试时段：

1. 临时切换 `global`。
2. 在 `GLOBAL` 中选择 `chain-hop2-exit` 或住宅节点。
3. 保持固定入口 A。
4. 用明确进入该 Mihomo 实例的浏览器访问可信的出口 IP 查询服务。
5. 查看连接记录，核对住宅节点及实际链路。
6. 对照住宅服务提供的出口信息。

Windows/macOS 确认浏览器进入正确的系统代理、显式代理或 TUN。NAS 初次验证建议明确使用 NAS 的 7892 端口及 NAS 入站账号。

全局模式会影响同一内核的其他新连接，NAS 多用户场景应安排测试时段。策略切换后发起新连接，避免旧连接沿用原路径。

| 结果 | 优先核对 |
| --- | --- |
| 预期住宅 IP | 当前请求已通过预期出口，继续验证实际业务 |
| 入口 IP | 是否选错代理组或请求未使用住宅节点 |
| 本地宽带 IP | 是否绕过内核或使用直连 |
| 超时、认证失败 | 入口到住宅的可达性、凭据、DNS及测试服务 |

住宅 `server` 可能是服务商接入网关，不一定等于最终出口 IP。查询结果不单独证明住宅属性或长期固定。

### 8.5 恢复规则模式并检查分流

恢复 `rule` 和原策略选择，测试住宅业务、应直连的国内服务及内网服务。结合连接记录判断规则与节点。全局正常而规则模式异常时，优先检查分流选择。

### 8.6 单独验证 UDP

HTTP/HTTPS 测试不证明 UDP 正常。使用实际需要的游戏、语音等应用，确认 UDP 流量进入内核并采用预期出口，观察断流和丢包，核实入口与住宅服务均支持所需转发。

NAS HTTP 显式代理测试不能覆盖任意应用 UDP；应使用支持该流量的 SOCKS5 或正确部署的 TUN 路径。

### 8.7 更换入口对比并恢复设置

至少对比两个入口，记录结果：

| 入口 | 入口测试 | 住宅链路测试 | 出口 IP | 实际业务 | 测试时间 |
| --- | --- | --- | --- | --- | --- |
| A | 待验证 | 待验证 | 私密记录 | 待验证 | 待填写 |
| B | 待验证 | 待验证 | 私密记录 | 待验证 | 待填写 |

避免将真实 IP、凭据或敏感日志提交到公共仓库。完成后恢复原模式及策略选择。
