## 2. P01：产品目标与范围

软件暂定名 **Skyline Configurator（Skyline 配置生成器）**。首版是 Windows 11 x64 桌面工具，界面为简体中文。用户选择目标环境、输入订阅和住宅 SOCKS5 代理信息、选择路径，生成可交给 Mihomo 客户端或 NAS Mihomo 服务加载的 YAML。

Windows 软件负责生成 Windows 和 NAS 两类配置，并不在 NAS 上运行。desktop 模板本身继续保持原有跨平台适用范围，首版软件只验证 Windows 输出用途。

首版包含：

- 两种模板选择，1–6 条有效订阅，一组住宅代理。
- 四个住宅字段：server、port、username、password。
- 环境参数、配置预览、结构校验、文件保存、导入说明。
- 内置模板、本地仓库模板读取、用户主动触发的 GitHub 模板更新。
- 自动生成控制密钥及 NAS 入站凭据。
- Windows 便携版、源码、测试及使用文档。

首版不包含：代理服务运行、系统代理或路由修改、自动部署 NAS、订阅转换云服务、任意规则编辑器、多住宅出口、账号系统、软件自动安装升级、其他平台 GUI。

兼容对象是通过实测的 **Mihomo 内核客户端**，不是所有冠以 Clash 名称的旧版软件。发布时列出实际测试的客户端及内核版本，不能仅凭品牌名承诺支持。

“可以导入”指格式和引用正确且符合验收内核要求；“实际可联网”还依赖有效服务、目标网络、资源下载和运行权限。软件必须准确区分二者。

与首版软件提案相比，本方案取消“默认自动选择入口”和“NAS 默认关闭 TUN”的建议，以尊重当前模板与已确认优化方案。显式代理模式仅是用户主动选择的输出选项。

## 4. P03：用户流程与网络参数取舍

### 4.1 常规流程

1. 打开软件，默认选择 Windows 电脑。
2. 输入至少一条订阅。
3. 填写住宅服务器、端口、用户名、密码。
4. 首次设置目标环境的本地 DNS；已有环境资料时自动回填。
5. 选择保存文件路径。
6. 点击“生成配置文件”。
7. 本地检查通过后保存，显示路径及导入说明。

默认文件名为 `skyline-desktop.yaml` 或 `skyline-nas.yaml`。NAS 用户可在保存对话框中直接命名为服务需要的 `config.yaml`。

### 4.2 必须明确的需求取舍

当前模板在有效字段中使用固定本地 DNS 示例。订阅及住宅四项信息无法决定目标网络 DNS，尤其不能用 Windows 电脑的 DNS 推断远端 NAS 网络。

**本方案推荐：首次设置额外填写“目标网络本地 DNS”，后续允许复用非敏感环境资料。** 它应能解析目标网络私有域名，且不能把同类查询转发回该 Mihomo 实例。不能猜测路由器地址、静默保留示例，或将删除私有 DNS 策略描述为无行为变化。

如果用户坚持任何时候都只输入订阅和四个住宅字段，需要另行同意一种 DNS 策略变更；当前方案不暗中进行这种变更。软件不得以“生成完成”承诺未知网络中的内网名称一定可解析。

Windows 同机 DNS 检测最多用于提供候选地址，仍由用户选择；不保证能识别 VPN、虚拟网卡或间接转发循环。NAS 不默认采集本机 DNS。

## 5. P04：界面与交互

采用一个主窗口、分区表单和折叠高级设置。建议初始约 960×760 DIP，支持滚动、键盘操作、屏幕阅读标签和 100%–200% 缩放。窗口过小时纵向布局，生成按钮保持易于找到。

| 区域 | 主要内容 |
| --- | --- |
| 顶部 | 软件名称；当前模板类型、版本和来源 |
| 使用环境 | Windows 电脑 / NAS；NAS 的透明代理与显式代理选项 |
| 代理订阅 | 一行起步；添加、删除、启停；最多六条启用项 |
| 住宅 SOCKS5 代理 | 四个字段；端口可预填 1080，但明确需核对服务端口 |
| 环境参数 | 目标网络本地 DNS；可保存为非敏感环境资料 |
| 高级设置 | TUN、端口、UDP、NAS 入站账号和控制接口参数 |
| 输出 | 原生保存对话框、完整目标路径 |
| 操作区 | 预览配置、生成配置文件 |
| 结果区 | 校验结果、打开文件夹、导入说明；NAS 凭据显示/复制 |

密码默认遮蔽；订阅可聚焦编辑、失焦遮蔽。预览默认脱敏，用户主动切换后才显示完整凭据。复制完整配置属于明确操作，不自动写剪贴板。

错误在字段下方显示，同时提供顶部概要并定位首个错误。已启用的空订阅行属于错误，不能静默忽略；新增后未使用的行可删除或停用。

生成期间禁用重复提交，网络更新可取消。修改输入后旧预览及校验结果失效。切换目标保留通用输入，环境专属参数分开保存。

不设置“住宅认证成功”“网络正常”等未经实际检查的状态。

## 6. P05：字段映射与校验契约

| 输入/选项 | 修改位置 | 校验与行为 |
| --- | --- | --- |
| 目标类型 | 模板选择 | desktop 或 nas，缺失模板阻止生成 |
| 第 n 条订阅 | proxy-providers.my-subscription-n.url | HTTP/HTTPS URL，至少一条；优先 HTTPS，不重编码 token |
| 订阅启停 | provider 及所有对应 use | 同步修改，保持现有健康检查、override 和周期 |
| server | 唯一目标住宅节点.server | 域名、IPv4、IPv6；不接受 scheme、路径或嵌入端口 |
| port | 同一节点.port | 1–65535 整数，不能为空 |
| username/password | 同一节点对应键 | 默认必填，按原字符串保留，不 trim、不做 Unicode 归一化 |
| 无需住宅认证 | 同一节点认证字段 | 高级选项，同时移除 username/password |
| 本地 DNS | dns.nameserver-policy 的 geosite:private | 首版接受一个 DNS IP，替换示例；高级域名策略暂不启用 |
| 控制密钥 | 顶层 secret | 独立随机值或用户明确提供的非空值 |
| NAS 入站认证 | 顶层 authentication | 自动生成或用户填写，与住宅账号隔离 |
| NAS 模式 | tun.enable，必要时 tun.auto-redirect | 默认保持模板；显式代理模式关闭二者，保留其余参数 |
| 保存地址 | 输出路径 | YAML 扩展名、可写、非源模板，不把路径写入代理节点 |

订阅使用稳定的 1–6 槽位；删除第 2 条不必重编号第 3 条，保留对应前缀、路径及状态可读性。重复 URL 给出提示并阻止无意义的重复启用，比较不能改变原始查询参数。

server 去除两端误粘贴空白；住宅凭据保留空格。疑似换行或控制字符明确报错，不能偷偷删除。所有凭据始终作为 YAML 字符串，防止 `true`、`null`、`00123` 等被改变类型。

本地 DNS 排除明显无效的 unspecified、组播等地址；明显自指地址可提示。跨设备和间接转发循环无法单靠静态检查证明不存在，导入说明要求部署验证。

静态引用检查覆盖所有 use，而不是只硬编码三处替换。住宅节点由模板清单指定稳定名称，不假定 proxies 数组第一项就是它。找不到、出现重名或拓扑不符时拒绝猜测。

## 7. P06：生成内容与保留范围

生成器基于 YAML 结构修改，不进行全局占位文本替换。保留未知合法字段，不能仅映射有限强类型属性后把其他字段丢弃。

允许的默认变更：

- 填写住宅四项信息。
- 填写已启用订阅，移除未启用的模板 provider 及其 use 引用。
- 填写目标本地 DNS。
- 替换控制密钥以及 NAS 入站账号占位符。
- 添加不含凭据的生成说明：生成器版本、模板版本、提交标识。

仅在明确选择高级选项时修改相应端口、TUN、UDP或认证字段。每次预览展示脱敏的“与模板相比修改了什么”。未列入修改集合的配置做语义一致性测试。

默认保留：规则顺序、所有业务组候选顺序、入口手动优先、住宅 dialer-proxy、出口 select 类型和完整健康检查、DNS 主体、IPv6、嗅探、路由排除、订阅更新策略、provider 路径和 GEO 资源策略。

生成器不向住宅出口组添加 DIRECT 或入口节点兜底，不把健康检查失败当作绕过住宅的理由。AI_non_cn 保持只有住宅出口候选；其他组保留现有手动选用入口组的能力。

入口测速检查入口；住宅测速经当前入口和住宅代理。两者不能合并为同一个状态。HTTP 204 成功不等于 UDP、住宅属性、固定出口或所有业务成功。

源模板注释完整保留在仓库；首版输出允许使用规范化排版及简短注释，不承诺逐字保留注释。原模板永不通过序列化回写。若后续要求完整注释往返，作为单独范围评估。

## 8. P07：NAS 的三类凭据与部署模式

| 凭据 | 用途 | 来源 |
| --- | --- | --- |
| 住宅用户名/密码 | Mihomo 连接住宅 SOCKS5 服务 | 用户填写 |
| NAS 入站用户名/密码 | 其他设备连接 NAS 7892 | 默认自动生成，可自定义 |
| 控制接口 secret | 面板连接 Mihomo API | 默认自动生成，可自定义 |

随机值使用操作系统密码学随机数。控制密钥使用至少 32 字节随机数据的安全文本编码；入站密码使用至少 24 字节随机数据，生成用户名及密码不含冒号、换行等分隔字符。自定义入站用户名/密码按实现支持范围校验，避免 authentication 拼接歧义。

同一编辑会话内保持生成凭据稳定；预览、选择另一个保存路径、重试保存不旋转凭据。点击“重新生成密钥”或新建配置才轮换。重新打开软件生成新配置默认会生成新密钥，需要沿用旧值时在高级设置输入。

NAS 默认 **沿用模板透明代理模式**，保留 system TUN、auto-route、auto-redirect 和 IPv6。提供主动选择的“仅显式代理”模式：关闭 TUN 与 auto-redirect，仍保留 mixed-port、分流规则和认证。不得因此修改仓库模板的默认值。

结果页给出入站账号、控制密钥的分别用途。可主动复制，不额外自动落盘一份明文密码说明。配置文件本身已经含有这些信息。

模板当前监听范围、允许网段、CORS 保留，可在高级设置主动调整。不将 lan-allowed-ips 错当控制接口或 DNS 的访问控制。部署说明解释防火墙、容器端口、网络命名空间、TUN 设备与权限；生成器不会配置这些基础设施。

## 9. P08：模板来源和更新

三个显式来源，界面始终显示实际选用者，不静默切换：

1. **内置模板（默认）**：从仓库两套文件打包，离线可用。
2. **本地仓库**：用户选择仓库根目录，读取 Mihomo 下两套文件；适合作者修改后立即测试，无需先推送 GitHub。路径是设置，不把本机路径写死到发布版。
3. **GitHub 发布模板**：从固定仓库 fmSun686yu/skyline 的正式模板发布包更新，不在每次启动无条件跟随分支 HEAD。

拟新增模板清单，记录模板 ID、显示版本、相对路径、SHA-256、契约版本、生成器版本范围、目标节点/入口组、受支持订阅槽位和必填环境字段。模板版本不能只依赖读取注释；清单与 YAML 一起发布。

本地编辑导致哈希变化时标记“本地修改版”，执行完整契约检查；不能要求本地作者每次编辑都伪装成已发布模板。正式更新包严格比对哈希和版本。哈希用于完整性，来源真实性依赖受信任仓库与 HTTPS 发布流程，不能把哈希当签名。

更新：下载至暂存目录 → 限制包大小、拒绝路径穿越 → 校验完整性和兼容性 → 原子切换模板缓存 → 保留一个上版以便回退。失败保留当前可用模板。无网络不阻止使用内置或已缓存模板。

自动生成使用一次固定模板快照；更新或外部编辑不能改变正在预览的内容。输入、模板或高级设置改变后重新生成预览。

## 10. P09：技术选型与架构

推荐 **C# + .NET 10 + WPF + MVVM + YamlDotNet**。

WPF 适合本轮 Windows 原生窗口、表单和保存对话框需求；.NET 10 提供 WPF Fluent 样式改进。[Microsoft 文档](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/whats-new/net100)

YamlDotNet 提供 YAML 解析与序列化功能；开发开始时锁定验证过的依赖版本，不承诺默认序列化保留所有注释。[YamlDotNet 官方仓库](https://github.com/aaubry/YamlDotNet)

核心生成逻辑不依赖 WPF、Windows 路径、网络或用户目录。将来跨平台可以复用核心逻辑，但 WPF 界面需要替换；本轮不提前承担跨平台 GUI 成本。

建议新增结构（以下相对仓库根目录）：

```text
src/
  Skyline.App/             窗口、视图模型、用户交互
  Skyline.Core/            输入模型、模板契约、生成和校验
  Skyline.Infrastructure/  模板来源、更新、文件写入、设置
tests/
  Skyline.Core.Tests/
  Skyline.IntegrationTests/
Mihomo/manifest.json
docs/change-plans/         软件及模板设计方案继续集中存放
docs/user-guide.zh-CN.md
.github/workflows/        构建、测试、发布打包
Skyline.sln
```

主要组件：TemplateRepository、TemplateContractValidator、ConfigurationGenerator、ConfigurationValidator、AtomicFileWriter、SettingsStore。核心生成接口接收模板快照、表单和已生成密钥，返回 YAML、脱敏变更摘要及错误，不自行访问互联网。

不需要数据库、云服务、登录系统或后台常驻进程。模板缓存和非敏感偏好放在当前用户 LocalAppData 下；用户配置仅写到选择的文件位置。

## 11. P10：生成与写盘流程

1. 捕获当前输入及模板快照，拒绝重复生成。
2. 验证字段和模板契约，包括重复 YAML 键和单文档结构。
3. 解析 YAML 为保留未知字段的结构模型。
4. 定点应用 P06 允许的变更。
5. 验证节点/组名称唯一、provider 引用、规则目标、代理依赖无环、缓存路径唯一。
6. 验证有效字段中无已知待替换占位符；注释中的示例不作为运行字段错误。
7. 序列化为 UTF-8 YAML，重新解析，确认数值类型、字符串内容和结构未变。
8. 原生保存对话框选择目标；已有文件仅覆盖一次明确确认的目标。
9. 在目标目录创建临时文件，写入并刷新，再以文件系统支持的原子替换或重命名完成保存。
10. 成功后显示文件路径及本次检查范围；失败清理自己创建的临时文件，保留原文件。

拒绝目标路径等于任一选用源模板，考虑路径大小写、规范化及文件标识，避免覆盖模板或其链接指向。覆盖时校验文件是否在确认后被其他进程修改。目标目录不可写、文件被占用或网络共享不支持预期操作时明确报错，不先删除旧文件。

生成不需要管理员权限。软件不尝试给不可写目录提升权限，用户可另选目录。TUN 运行权限属于代理客户端部署问题。

## 12. P11：验证层次和兼容性边界

### 12.1 每次生成执行

输入格式、模板契约、YAML 语法和类型、静态引用、循环、路径冲突、占位字段及输出写入检查。不访问住宅服务器，不下载用户订阅，不调整正在运行的客户端。

### 12.2 开发和发布执行

使用固定版本的 Mihomo 在独立工作目录验证。Windows 输出在 Windows 内核环境测试，NAS 输出在匹配的 Linux/NAS 或容器环境验证，不能让 Windows 的通过结果代替 NAS 平台验收。

如果内核检查会下载资源，明确记录网络前提、访问范围、超时和结果。需要缓存的检查使用隔离目录；测试不得读取或清空真实客户端工作目录。

### 12.3 部署实测

分别执行干净工作目录首次启动与缓存重启；确认订阅、MRS 和 DNS 实际依赖的 GEO 数据。provider 相对路径属于内核工作/HomeDir，而非必然属于输出 YAML 所在目录。[官方 provider 路径说明](https://wiki.metacubex.one/config/proxy-providers/)

确认客户端是否覆盖端口、TUN、DNS 和 secret，并在文档中记录；同名代理组的历史选择可能覆盖首次默认顺序，因此不能保证导入后一定选择列表第一项。

固定入口进行住宅 HTTP 检查、错误住宅凭据失败且不绕过、恢复后成功、入口切换后重新检查、实际出口与业务验证。UDP 单独验证。沿用现有 README 的隔离测试方法。

软件首版不提供“自动联网验证全部链路”按钮，避免把普通 TCP 探测误当完整链路检查。此功能如后续加入，需独立内核、隔离工作目录及明确的测试网络路径设计。

## 13. P12：隐私与错误处理

默认不持久化订阅 URL、住宅账号密码、自动生成的凭据；仅在本次会话和输出 YAML 中使用。环境 DNS、选用目标、模板来源及输出目录可由用户选择记住；允许清除这些设置。

导出 YAML 必须含真实凭据才能运行。界面在保存区域用简短提示说明文件含订阅和密码，不增加每次生成的额外审批流程。默认保存到用户文档目录，不默认放入 Git 仓库。

日志只记录错误类别和脱敏信息，不打印 YAML、完整订阅地址、密码或含凭据的底层异常。模板更新请求不携带表单内容。不收集遥测或默认上传崩溃报告。

清理临时文件属于尽力清理，不承诺托管内存、操作系统缓存和磁盘中的敏感内容可被绝对擦除。首版不提供“保存密码”功能，避免不必要的凭据存储系统。

| 场景 | 行为 |
| --- | --- |
| 输入缺失或格式错误 | 字段内提示，阻止生成 |
| DNS 环境参数未设置 | 引导填写目标网络 DNS，不猜测 |
| 模板结构变动不兼容 | 显示模板版本和具体缺失项，允许主动切回内置模板 |
| 更新失败 | 保留旧模板，当前生成流程可继续 |
| 保存失败 | 原文件保持，提供重试或另存位置 |
| 取消保存 | 不显示成功，不留下新目标文件 |
| 尚未联网测试 | 显示“本地配置检查通过，连接状态未测试” |

## 16. P15：审阅决策和后续扩展

建议本次一并确认：

1. 使用 Windows 原生 WPF/.NET 10 方案，首版 x64 便携版。
2. 1–6 条订阅、一组 SOCKS5 住宅代理；不做远程订阅转换。
3. 按最新模板保留入口手动优先、NAS TUN 默认和现有网络策略。
4. 首次补充目标网络本地 DNS，允许记住非敏感环境资料。
5. 软件自动生成独立控制密钥、NAS 入站账号；默认不持久化秘密。
6. 三种明确模板来源；本地修改可直接用于验证，正式更新需要契约检查。
7. 首版默认仅作本地检查，内核和真实网络验证纳入开发发布验收。

后续可独立规划：多住宅出口、HTTP/HTTPS 住宅协议、加密本地配置档案、完整链路诊断、NAS 部署助手、其他平台 GUI。它们不阻塞首版核心流程，也不提前加入当前范围。
