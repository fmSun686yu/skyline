# Skyline Configurator 分阶段开发计划 v1

## 1. 状态与依据

| 项目 | 状态 |
| --- | --- |
| 产品设计 | [软件设计方案 v5](2026-09-18-skyline-configurator-design-v5.md) 已获用户审核通过 |
| 本计划 | 用户已分别批准 S01、S02 实施计划，按阶段执行 |
| 软件开发 | 用户已指示进入 S02；S02 实现完成、验证通过，待审核；S03–S07 未开始 |
| 阶段安排 | S01–S07，依次实施、逐阶段交付审核 |

本计划细化 v5 的 P14 概要阶段，不改变已批准产品范围。阶段编号独立于方案和软件版本号。S01、S02 已按用户批准范围实施，未修改源模板、未运行真实代理服务；详见 [S01 交付报告](../stages/S01-report.md)和 [S02 交付报告](../stages/S02-report.md)。

## 2. 执行规则

1. 本计划审核通过后，先执行 S01，不一次性完成整个软件。
2. 每阶段完成后交付具体成果、验证结果和未完成事项，暂停等待用户审核；用户确认后再进入下一阶段。
3. 阶段内自主完成约定范围内的实现、调试及必要修复，不为每个小步骤反复要求确认。
4. 审核提出的问题优先在当前阶段修复。已批准产品行为需要改变时，先说明影响并取得确认，不借实现扩展功能。
5. 每阶段开始重新查看仓库状态、相关指令和目标文件，保留用户已有修改。阶段记录区分“实现完成”“验证通过”“用户审核通过”。
6. 检查尽早进行：核心逻辑在 S02 验证，写盘在 S03 验证，界面在 S04 验证，多语言在 S05 验证；S06 负责平台和真实环境集成，不把全部测试推迟到最后。
7. 软件始终遵循每次 DNS 必填、版本绑定内置模板、ZIP 解压即用、六语且默认 en-US、无高级网络设置、基础凭据自动且可编辑的要求。
8. 示例和自动化测试只用虚构凭据。真实部署资料在用户本地私密文件中使用，不要求在对话或公共仓库提供。
9. 未具备环境的验证标为“未验证”；不能以静态检查、模拟结果或另一平台通过代替。遇到前置条件缺失，报告具体条件和影响，由用户决定补齐或明确调整后续安排。
10. 阶段交付不自动意味着 Git 提交、推送、公开发布或部署；这些动作按届时指令执行。

## 4. S01：工程与内置模板基础

**目的：**建立能构建、能运行、模板来源固定的开发基础。

工作范围：

- 检查本机 .NET SDK、Windows 构建条件和工具可用性；缺少依赖时明确处理方式。
- 建立 App、Core、Infrastructure 和测试项目，固定 SDK/依赖版本及引用方向。
- 建立最小 WPF 启动窗口，暂不实现业务表单；英文资源基础可用。
- 建立模板清单，将两套 YAML 和清单嵌入程序集，记录版本、哈希、目标节点及订阅槽位。
- 确认运行时不读取仓库目录、外部模板或 GitHub。
- 补充构建说明和必要忽略规则，避免忽略公共模板。

交付：可构建的工程、最小启动窗口、内置模板目录组件、版本绑定清单、开发环境记录。

验证：构建成功；标准用户启动；两套嵌入资源与源模板哈希一致；资源异常可识别；改变外部同名文件不会改变已构建程序的模板。

审核重点：目录是否清晰、模板绑定正确、项目范围未扩展。覆盖 A10 的基础部分。此阶段不生成用户配置、不修改模板网络行为。

## 5. S02：配置生成核心

**目的：**在界面联调前证明配置生成正确，并严格限制可修改参数。

工作范围：

- 实现 v5 P05 的输入模型与字段校验，错误返回代码和参数，支持后续本地化。
- 实现模板契约检查、结构化 YAML 读取、定点字段修改和序列化后复核。
- 支持 1–6 条订阅及非连续槽位，同步 provider 与所有 use 引用。
- 实现住宅四项、本地 DNS、控制密钥和 NAS 入站账号写入。此阶段将凭据作为输入，随机生成及完整会话行为由 S03 实现。
- 检查类型、重名、静态引用、循环、缓存路径和占位字段。
- 验证允许修改集合以外的数据结构与原模板相同，尤其是 TUN、UDP、端口、访问范围和 CORS。
- 产出脱敏变更摘要，预览正文和摘要分离。

交付：可独立测试的生成引擎、虚构凭据的 Windows/NAS 样例文件、允许变更对照和测试报告。

验证：覆盖 A01–A06、A24 的核心部分；测试特殊字符、无效端口、缺失 DNS、有效 DNS 恰好等于示例地址、未知字段保留等。条件具备时尽早用固定内核做隔离加载检查，发现兼容问题尽早修复；不将其等同 S06 真实联网验证。

审核重点：样例配置内容正确，未出现意外网络策略变更。此阶段不提供完整 GUI 或承诺住宅连接有效。

## 6. S03：文件保存、凭据与会话管理

**目的：**保证数据不会写错位置、意外丢失或在重试中改变。

工作范围：

- 实现独立随机控制密钥、NAS 用户名和密码，支持逐字段重新生成及手动覆盖。
- 实现新建、切换目标、预览、取消、失败重试、保存成功及开始下一份配置的状态规则。
- 实现 DNS 每次重新填写，凭据不写偏好和日志；只有语言等允许的非敏感设置可保存。
- 实现输出路径校验、临时写入、原子替换、覆盖冲突检查和失败清理。
- 保护程序文件和公共模板位置，错误信息脱敏。

交付：文件保存组件、凭据生成和会话组件、状态转换说明、可重复执行的测试。

验证：A07–A09、A16、A25 中组件级行为，包括中文/空格路径、无权限、文件占用、取消、写入故障、保留旧文件、字段单独重新生成、NAS 字段在 Windows 目标下不参与输出等。

审核重点：自动值可用、手动值不被覆盖、失败重试不旋转凭据、成功页内容与文件一致。原生对话框与按钮实际体验在 S04 完成。

## 7. S04：英文完整界面与主流程

**目的：**交付第一版用户可以实际操作的完整生成工具，优先审核流程是否简单。

工作范围：

- 实现主窗口、Windows/NAS 选择、订阅列表、住宅四项、必填 DNS、控制密钥、NAS 入站账号及保存区域。
- 所有管理凭据在基础表单自动填写，可编辑、显示/隐藏、复制和逐项重新生成。
- 联通 S02/S03，完成只读脱敏预览、字段报错、原生保存对话框、结果页和打开文件夹。
- 首先交付英文界面，但所有应用文案从资源读取；语言服务接口及刷新机制为 S05 留好位置，不展示不可用的语言选项。
- 不添加任何高级设置区域、模式开关、监听端口编辑或外部模板入口。
- 产出自包含 ZIP 预览包供用户体验；这不是最终发布版。

交付：英文功能预览包、界面截图或演示说明、主流程验证记录。

验证：Windows/NAS 完整生成；字段可发现、错误能定位、DNS 与凭据状态正确；100/150/200% 缩放和键盘导航；初步解压启动检查。覆盖 A11、A24 及 A07–A09/A25 的 UI 层。

审核重点：用户能否顺利填写并保存，自动凭据是否好理解，表单是否仍存在不必要的门槛。审核通过后再集中扩展全部语言与文案。

## 8. S05：六语、本地化与离线帮助

**目的：**完成首版要求的全部语言，并验证切换不会影响配置。

工作范围：

- 完成 en-US、zh-CN、zh-TW、ja-JP、de-DE、fr-FR 资源与语言菜单。
- 模板说明 `SlotsFormat` 的六语文案统一采用下述“最多支持的订阅链接数”表述，不再向用户显示“订阅槽位”。Windows 和 NAS 共用此资源键；`{0}` 取模板清单中的数量，当前为 6。英文已在 S01 修改，其余语言在 S05 资源实现时同步采用。

| 语言 | `SlotsFormat` 文案 |
| --- | --- |
| en-US | Up to {0} subscription links · SOCKS5 residential proxy |
| zh-CN | 最多 {0} 个订阅链接 · SOCKS5 住宅代理 |
| zh-TW | 最多 {0} 個訂閱連結 · SOCKS5 住宅代理 |
| ja-JP | サブスクリプションリンクは最大{0}件 · SOCKS5 住宅用プロキシ |
| de-DE | Bis zu {0} Abonnement-Links · SOCKS5-Proxy mit Wohn-IP-Adresse |
| fr-FR | Jusqu’à {0} liens d’abonnement · Proxy résidentiel SOCKS5 |

后续工作项：

- 首次启动固定 en-US；保存有效语言偏好；立即切换、英文回退、清除偏好均符合 P16。
- 完成本地化提示、错误、无障碍标签、导入说明和六语离线指南。
- 验证德法长文本、中日输入、字体回退、占位参数和翻译术语。
- 比较固定输入与密钥在六语下生成的 YAML 一致。

交付：统一六语预览 ZIP、六语使用说明、本地化校验和人工审阅记录。

验证：A19–A23，六种语言分别覆盖正常生成和常见错误；切换不清空 DNS、不旋转凭据、不更改配置字段；断网也能使用全部语言。

审核重点：语言切换和显示完整，主要术语可理解，默认英文行为正确。发布前不得以英文回退掩盖未完成翻译。

## 9. S06：内核兼容与目标环境验证

**目的：**验证输出在实际目标环境中可加载和使用，并修复集成问题。

工作范围：

- 记录测试用 Windows 客户端、Mihomo 内核、Linux/NAS 或容器版本。
- 在隔离配置和工作目录验证两种输出；不使用 Windows 检查结果代替 NAS 验收。
- 分别验证空缓存启动、资源下载、已有缓存重启，检查客户端覆盖行为。
- 使用本地私密有效资料验证住宅链路、错误凭据失败且不绕过、恢复及入口切换。
- 验证实际出口、规则分流、内网访问和需要的 UDP 场景。
- 修复阶段内发现的问题并运行受影响的回归测试。

交付：兼容性矩阵、A12–A15 结果、缺陷修复记录、候选版本。

前置条件：匹配的目标运行环境及有效测试资料；具体准备项在本阶段开始前一次性列明。故障注入仅在隔离测试副本中进行，不操作共享生产配置。

审核重点：哪些平台与链路确实验证通过，哪些仍有限制。若目标环境缺失，只能交付已完成部分和明确的未验证项，不能宣布完整兼容验收通过；是否先准备 S07 候选包由用户明确决定，不自动跨过该门槛。

## 10. S07：便携包、构建流程与最终交付

**目的：**把已审核的软件整理为可复现构建、可直接下载解压使用的最终产物。

工作范围：

- 完成构建/测试/打包工作流，核对软件版本、内置模板版本及哈希、六语资源、依赖和许可。
- 构建自包含 Windows x64 ZIP，不提供安装包，不要求用户另装 .NET。
- 在干净 Windows 11 标准用户环境验证完整解压、首次启动、离线六语、生成保存。
- 验证整包升级、新旧目录并存、回退及已有配置不被自动改写。
- 汇总变更记录、六语指南、模板绑定信息、兼容性和未验证项，生成包校验和。

交付：`Skyline-<软件版本>-win-x64-portable.zip`、校验和、源码与构建说明、许可资料、最终测试报告及使用指南。

验证：完成 A17–A18、最终包上的 A10/A16/A23，以及必要的端到端冒烟测试；汇总 A01–A25，明确所有结果及证据。此前通过的测试不无理由重复，打包改变的加载路径和依赖需要重新验证。

审核重点：用户无需开发环境或安装流程即可使用，发布物与已审核源码/模板一致。此阶段先交付本地完整产物供审核，公开上传或发布另行按用户指令执行。

## 11. 阶段交付报告格式

每阶段结束提供：

- 本阶段实现内容与对应文件/产物链接。
- 用户可操作或检查的步骤；后台阶段提供样例和对照结果。
- 已通过、失败及未执行的验证，分别说明原因。
- 对 v5 行为的影响及是否存在范围变更。
- 当前问题、所需条件和下一阶段范围。
- 明确提示当前阶段等待审核，不自动继续下一阶段。
