## 2. P01：产品目标与范围

软件暂定名 **Skyline Configurator（Skyline 配置生成器）**。首版是 Windows 11 x64 桌面工具，支持英文（美国）、简体中文、繁体中文、日文、德语和法语；首次启动默认英文（美国），不随操作系统语言自动切换。用户选择目标环境、输入订阅和住宅 SOCKS5 代理信息、选择路径，生成可交给 Mihomo 客户端或 NAS Mihomo 服务加载的 YAML。

Windows 软件负责生成 Windows 和 NAS 两类配置，并不在 NAS 上运行。desktop 模板本身继续保持原有跨平台适用范围，首版软件只验证 Windows 输出用途。

首版包含：

- 六种完整界面语言、语言切换与离线帮助，统一打包；语言偏好可保存。
- 两种模板选择，1–6 条有效订阅，一组住宅代理。
- 四个住宅字段：server、port、username、password。
- 环境参数、配置预览、结构校验、文件保存、导入说明。
- 与软件版本固定绑定的两套内置模板；运行时只选择 Windows/NAS 用途。
- 主表单中自动填写控制密钥及 NAS 入站凭据，允许用户直接编辑。
- 下载完整 ZIP、解压后直接运行的 Windows 自包含便携版，以及源码、测试及使用文档。

首版不包含：代理服务运行、系统代理或路由修改、自动部署 NAS、订阅转换云服务、任意规则编辑器、多住宅出口、账号系统、软件自动安装升级、其他平台 GUI。

不再提供高级设置页或折叠区。TUN 开关、NAS 工作模式、住宅代理 UDP、住宅认证方式、本地代理监听端口、NAS 监听范围/访问网段/CORS 均按内置模板输出，不提供隐藏开关或设置文件覆盖入口。住宅服务器端口仍是必要的基础输入，不属于已移除的本地监听端口设置。

兼容对象是通过实测的 **Mihomo 内核客户端**，不是所有冠以 Clash 名称的旧版软件。发布时列出实际测试的客户端及内核版本，不能仅凭品牌名承诺支持。

“可以导入”指格式和引用正确且符合验收内核要求；“实际可联网”还依赖有效服务、目标网络、资源下载和运行权限。软件必须准确区分二者。

## 4. P03：用户流程与网络参数取舍

### 4.1 常规流程

1. 打开软件，首次使用显示英文（美国），默认选择 Windows 电脑；可在顶部 Language 菜单切换语言，之后启动使用已保存的有效语言偏好。
2. 输入至少一条订阅。
3. 填写住宅服务器、端口、用户名、密码。
4. 填写本次配置目标网络的本地 DNS，此项每次必填。
5. 控制接口密钥已经自动填写；NAS 目标还自动填写入站用户名及密码。可直接沿用，也可在主表单改成自己的值，无需选择自动/手动模式。
6. 选择保存文件路径。
7. 点击“生成配置文件”。
8. 本地检查通过后保存，显示路径及导入说明。

默认文件名为 `skyline-desktop.yaml` 或 `skyline-nas.yaml`。NAS 用户可在保存对话框中直接命名为服务需要的 `config.yaml`。

本方案中的中文按钮和提示用于说明语义，实际界面使用当前语言的对应文本，例如英文生成按钮为“Generate configuration”。默认文件名及配置标识不随界面语言变化。

### 4.2 每次必填目标网络本地 DNS

当前模板在有效字段中使用固定本地 DNS 示例。订阅及住宅四项信息无法决定目标网络 DNS，尤其不能用 Windows 电脑的 DNS 推断远端 NAS 网络。

**按用户要求，主界面固定增加“目标网络本地 DNS”必填输入框，Windows 和 NAS 配置均需每次手动填写。** 它应能解析目标网络私有域名，且不能把同类查询转发回该 Mihomo 实例。不能猜测路由器地址、静默保留示例，或将删除私有 DNS 策略描述为无行为变化。

首次打开、新建配置、切换 Windows/NAS 目标或成功保存后开始生成下一份配置时，该输入框为空；不记住上次值、不从环境资料自动回填、不预填 192.168.50.1。保存成功后结果页可显示本次值，但下一次生成需重新填写。保存失败、取消保存或同一份配置的预览不清空已经填写的值，以便重试。

不提供本机 DNS 自动检测或代填。输入为空或格式错误时阻止生成。校验通过后写入 dns.nameserver-policy 的 geosite:private；软件不得以“生成完成”承诺未知网络中的内网名称一定可解析。用户主动填写的真实 DNS 即使恰好是 192.168.50.1 也可通过，不能仅因它等于模板示例就判错。

## 5. P04：界面与交互

采用一个主窗口和分区基础表单，不设高级设置。建议初始约 960×760 DIP，支持滚动、键盘操作、屏幕阅读标签和 100%–200% 缩放。窗口过小时纵向布局，生成按钮保持易于找到。

| 区域 | 主要内容 |
| --- | --- |
| 顶部 | 软件版本、当前内置模板类型和版本、语言菜单；无模板来源选择或更新按钮 |
| 使用环境 | 仅 Windows 电脑 / NAS，不显示 NAS 工作模式选项 |
| 代理订阅 | 一行起步；添加、删除、启停；最多六条启用项 |
| 住宅 SOCKS5 代理 | 四个字段；端口可预填 1080，但明确需核对服务端口 |
| 环境参数 | 目标网络本地 DNS，每次手动必填；不保存或回填 |
| 控制接口密钥 | Windows/NAS 均显示；默认自动填写，可编辑、显示/隐藏、复制或重新生成 |
| NAS 入站账号 | 仅选择 NAS 时显示用户名和密码；默认自动填写，可分别编辑，密码可显示/隐藏，可复制或重新生成 |
| 输出 | 原生保存对话框、完整目标路径 |
| 操作区 | 预览配置、生成配置文件 |
| 结果区 | 校验结果、打开文件夹、导入说明；NAS 凭据显示/复制 |

密码和控制密钥默认遮蔽，入站用户名正常显示；自动生成字段标注“已自动生成，可直接使用或修改”。提供简短用途说明，不要求用户先理解认证原理。订阅可聚焦编辑、失焦遮蔽。预览默认脱敏，用户主动切换后才显示完整凭据。复制完整配置属于明确操作，不自动写剪贴板。

错误在字段下方显示，同时提供顶部概要并定位首个错误。已启用的空订阅行属于错误，不能静默忽略；新增后未使用的行可删除或停用。

生成期间禁用重复提交。修改输入后旧预览及校验结果失效。切换目标保留订阅与住宅输入，但清空目标网络本地 DNS；控制密钥按目标在会话内分别保留，NAS 入站账号在 Windows 目标下隐藏且不参与校验或输出，切回 NAS 时恢复当前会话值。首次选择该目标时自动生成所需凭据。无模板下载进度、更新任务或本地仓库浏览入口。

不设置“住宅认证成功”“网络正常”等未经实际检查的状态。

界面文案、错误提示、帮助及无障碍标签统一使用 P16 的翻译资源。语言菜单以各语言自身名称显示，始终可见；切换无需重启，不清空当前表单、本地 DNS 或生成凭据，也不触发配置生成。正在写盘或打开模态对话框时，暂缓切换至操作结束。布局使用可伸缩宽度与换行，适应德语、法语长文本和中日文字形，不把固定宽度英文按钮作为全部语言的基准。

## 6. P05：字段映射与校验契约

| 输入/选项 | 修改位置 | 校验与行为 |
| --- | --- | --- |
| 目标类型 | 内置模板选择 | 仅加载本软件版本内置的 desktop 或 nas，缺失或校验失败阻止生成 |
| 第 n 条订阅 | proxy-providers.my-subscription-n.url | HTTP/HTTPS URL，至少一条；优先 HTTPS，不重编码 token |
| 订阅启停 | provider 及所有对应 use | 同步修改，保持现有健康检查、override 和周期 |
| server | 唯一目标住宅节点.server | 域名、IPv4、IPv6；不接受 scheme、路径或嵌入端口 |
| port | 同一节点.port | 1–65535 整数，不能为空 |
| username/password | 同一节点对应键 | 均必填，按原字符串保留；不提供无需认证选项，不 trim、不做 Unicode 归一化 |
| 本地 DNS | dns.nameserver-policy 的 geosite:private | 每次必填一个 DNS IP，替换示例；不持久化、不代填，不提供其他 DNS 策略编辑 |
| 控制密钥 | 顶层 secret | 基础字段，默认独立随机值，可直接编辑；有效非空值必需 |
| NAS 入站用户名/密码 | 顶层 authentication 中一组账号 | NAS 基础字段，默认自动生成，可分别编辑，均必填；与住宅账号隔离 |
| 保存地址 | 输出路径 | YAML 扩展名、可写、非源模板，不把路径写入代理节点 |
| 界面语言 | 仅界面资源和语言偏好 | 六种允许值之一，不映射到 YAML、不改变网络配置 |

订阅使用稳定的 1–6 槽位；删除第 2 条不必重编号第 3 条，保留对应前缀、路径及状态可读性。重复 URL 给出提示并阻止无意义的重复启用，比较不能改变原始查询参数。

server 去除两端误粘贴空白；住宅凭据保留空格。疑似换行或控制字符明确报错，不能偷偷删除。所有凭据始终作为 YAML 字符串，防止 `true`、`null`、`00123` 等被改变类型。

端口接受 ASCII 十进制整数，不接受本地化千位分隔符或小数。YAML 数值、布尔值、URL、IP、标识符的解析与输出使用固定规则，不受当前语言或系统区域格式影响。用户字段不会因为语言切换被翻译、重编码或修改大小写。

本地 DNS 排除明显无效的 unspecified、组播等地址；明显自指地址可提示。跨设备和间接转发循环无法单靠静态检查证明不存在，导入说明要求部署验证。

静态引用检查覆盖所有 use，而不是只硬编码三处替换。住宅节点由模板清单指定稳定名称，不假定 proxies 数组第一项就是它。找不到、出现重名或拓扑不符时拒绝猜测。

上述表格是完整的用户可编辑配置参数清单。输入模型不包含被移除的网络开关或覆盖字段；预览只读，不提供自由 YAML 编辑器绕过清单。住宅认证方式沿用用户名/密码形式，无认证住宅服务不属于本版支持范围。

## 7. P06：生成内容与保留范围

生成器基于 YAML 结构修改，不进行全局占位文本替换。保留未知合法字段，不能仅映射有限强类型属性后把其他字段丢弃。

允许的全部配置变更：

- 填写住宅四项信息。
- 填写已启用订阅，移除未启用的模板 provider 及其 use 引用。
- 填写目标本地 DNS。
- 替换控制密钥以及 NAS 入站账号占位符。
- 添加不含凭据的生成说明：生成器版本、模板版本、提交标识。

每次预览展示脱敏的“与模板相比修改了什么”。变更严格限于上述集合，无高级选项附加覆盖。除住宅四项字段和 NAS 入站凭据替换外，不变更认证相关行为。未列入修改集合的配置做语义一致性测试。

默认保留：规则顺序、所有业务组候选顺序、入口手动优先、住宅 dialer-proxy、出口 select 类型和完整健康检查、DNS 主体、IPv6、嗅探、路由排除、订阅更新策略、provider 路径和 GEO 资源策略。

同时逐字段保留 TUN 全部设置、住宅 udp 值、HTTP/SOCKS/mixed 与 DNS/控制接口监听地址和端口、allow-lan、bind-address、lan-allowed-ips、lan-disallowed-ips、skip-auth-prefixes 及 external-controller-cors。NAS 入站认证保持启用，仅用主表单的一组账号替换示例账号；Windows 不新增 NAS 入站认证。

生成器不向住宅出口组添加 DIRECT 或入口节点兜底，不把健康检查失败当作绕过住宅的理由。AI_non_cn 保持只有住宅出口候选；其他组保留现有手动选用入口组的能力。

入口测速检查入口；住宅测速经当前入口和住宅代理。两者不能合并为同一个状态。HTTP 204 成功不等于 UDP、住宅属性、固定出口或所有业务成功。

源模板注释完整保留在仓库；首版输出允许使用规范化排版及简短注释，不承诺逐字保留注释。原模板永不通过序列化回写。若后续要求完整注释往返，作为单独范围评估。

输出 YAML 键名、节点名、代理组名、provider 名称、规则和默认文件名均不本地化；生成器新增的简短注释固定使用英文，源模板注释不做运行时翻译。相同输入、内置模板及生成密钥下，六种界面语言产生相同 YAML。预览中的说明和脱敏变更摘要使用当前界面语言，配置正文保持原样。

## 8. P07：基础凭据及模板固定网络行为

| 凭据 | 用途 | 来源 |
| --- | --- | --- |
| 住宅用户名/密码 | Mihomo 连接住宅 SOCKS5 服务 | 用户填写 |
| NAS 入站用户名/密码 | 其他设备连接 NAS 7892 | 默认自动生成，可自定义 |
| 控制接口 secret | 面板连接 Mihomo API | 默认自动生成，可自定义 |

控制密钥是一个独立文本字段，不设计控制接口用户名/密码。NAS 入站账号是单独的用户名、密码两个字段，仅 NAS 目标显示。三者均直接位于基础表单，自动填好即可使用，也可逐项修改，无需额外打开设置页或切换手动模式。住宅用户名和密码来自服务商，仍由用户填写，不自动生成。

随机值使用操作系统密码学随机数。控制密钥使用至少 32 字节随机数据的安全文本编码；入站密码使用至少 24 字节随机数据；入站用户名采用 skyline_ 加随机后缀，避免复用住宅账号。生成用户名及密码不含冒号、换行等分隔字符。

手动填写的控制密钥和 NAS 用户名/密码不允许空值、纯空白或控制字符；本版 NAS 用户名和密码均拒绝冒号，避免 authentication 的分隔歧义。其他合法字符原样保存，不自动裁剪。清空字段后显示填写提示，并可点击对应字段“重新生成”；不在失焦或保存时偷偷用随机值替换用户输入。住宅认证字段按 P05 校验，不套用 NAS 的冒号限制。

同一份配置内保持生成及手动填写的凭据稳定；预览、语言切换、选择另一个保存路径、取消/失败重试不旋转凭据。每个字段的“重新生成”只替换对应字段，不修改其余字段。新建配置或保存成功后主动开始下一份配置时，清空旧会话凭据并为当前目标生成新值；成功结果页仍保留刚保存的凭据供查看和复制。重新打开软件也生成新值，需要沿用旧值时直接在基础表单填写。无论自动还是手动，都不保存到偏好或日志。

NAS **固定沿用内置模板透明代理设置**，保留 system TUN、auto-route、auto-redirect 和 IPv6；Windows 保留自己的 TUN 和端口设置。软件不提供关闭 TUN、选择 NAS 模式或调整 UDP 的操作。减少表单选项不消除 TUN 的部署前提，导入说明仍应简要交代客户端权限及 NAS 容器设备、网络权限和路由要求；软件不声称适用于未满足这些条件的任意 NAS 环境。

结果页给出入站账号、控制密钥的分别用途。可主动复制，不额外自动落盘一份明文密码说明。配置文件本身已经含有这些信息。

模板当前监听范围、允许网段、CORS 全部保留，无用户调整入口。不将 lan-allowed-ips 错当控制接口或 DNS 的访问控制。部署说明解释防火墙、容器端口、网络命名空间、TUN 设备与权限；生成器不会配置这些基础设施。

## 9. P08：与软件版本绑定的内置模板

每个软件版本只使用该版本内置的 desktop、nas 两套模板。用户选择的是配置用途，不选择模板来源或历史版本。构建时从仓库 Mihomo/desktop/config.yaml 和 Mihomo/nas/config.yaml 读取并嵌入程序资源；运行时不依赖仓库、外置 YAML 或网络。

拟新增构建用模板清单，记录软件版本与两套模板的准确版本、SHA-256、资源标识、契约版本、目标节点/入口组、受支持订阅槽位和必填环境字段。清单与模板一起嵌入程序。软件和模板版本号可以不同，但每个软件发行版本绑定唯一且不可动态更换的模板组合。

发布流程：维护仓库模板 → 更新模板版本及清单 → 更新软件版本 → 构建嵌入资源 → 执行生成和兼容性验证 → 发布新版完整软件 ZIP。即使程序逻辑不变，只要发布的模板内容变化，也要发布新软件版本，不覆盖旧版本对应的发布产物。

运行时检查内置资源完整性和结构；失败提示“内置模板损坏或版本不一致，请重新下载对应版本软件”，不接受外部替代模板。哈希用于检测资源不一致，不等同于软件数字签名。

不设计本地仓库选择、导入模板、GitHub 模板下载、独立模板更新、模板缓存或模板回退模块。用户升级时关闭旧软件，下载新版 ZIP 并解压到新目录，直接运行新版；需要回退时运行保留的旧版完整软件目录。已经生成的 YAML 不会自动改写。

基础输入或目标类型改变后重新生成预览。程序运行中的内置模板不变；修改仓库模板只影响后续重新构建的软件，不影响已发布程序。

这里限制的是生成器使用的基础模板。导出的 YAML 中现有订阅、规则集及 GEO 数据更新仍由 Mihomo 按模板原有策略执行，保持不变。

## 10. P09：技术选型与架构

推荐 **C# + .NET 10 + WPF + MVVM + YamlDotNet**。

WPF 适合本轮 Windows 原生窗口、表单和保存对话框需求；.NET 10 提供 WPF Fluent 样式改进。[Microsoft 文档](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/whats-new/net100)

YamlDotNet 提供 YAML 解析与序列化功能；开发开始时锁定验证过的依赖版本，不承诺默认序列化保留所有注释。[YamlDotNet 官方仓库](https://github.com/aaubry/YamlDotNet)

核心生成逻辑不依赖 WPF、Windows 路径、网络或用户目录。将来跨平台可以复用核心逻辑，但 WPF 界面需要替换；本轮不提前承担跨平台 GUI 成本。

建议新增结构（以下相对仓库根目录）：

```text
src/
  Skyline.App/             窗口、视图模型、用户交互、语言服务
    Resources/Strings/     六种语言的 .resx 文案资源
  Skyline.Core/            输入模型、模板契约、生成和校验
  Skyline.Infrastructure/  内置资源读取、文件写入、非敏感偏好
tests/
  Skyline.Core.Tests/
  Skyline.IntegrationTests/
Mihomo/manifest.json       构建用软件—模板版本绑定清单，随程序嵌入
docs/change-plans/         软件及模板设计方案继续集中存放
docs/user-guide/           六种语言的离线用户指南，英文为基准
.github/workflows/        构建、测试、发布打包
Skyline.sln
```

主要组件：EmbeddedTemplateCatalog、TemplateContractValidator、ConfigurationGenerator、ConfigurationValidator、AtomicFileWriter、SettingsStore。只保留内置模板读取实现，不预建远程下载、缓存或本地来源接口。核心生成接口接收内置模板快照、表单和已生成密钥，返回 YAML、脱敏变更摘要及错误，不自行访问互联网。

新增 LocalizationService 负责语言选择、资源查找和界面刷新；使用稳定资源键管理文本。核心校验返回错误代码、字段标识和脱敏参数，界面层生成本地化消息，避免核心逻辑依赖翻译文本。资源采用 .resx 及随软件发布的语言资源程序集，六种语言与本版本软件一起打包，无在线语言包和运行时翻译服务。

不需要数据库、云服务、登录系统或后台常驻进程。非敏感界面偏好可放在当前用户 LocalAppData 下，但不包含 DNS、订阅和凭据。没有模板缓存目录；用户配置仅写到选择的文件位置。便携版无需安装，但不承诺绝对零写入用户目录；无法写入偏好时仍可继续生成。

## 11. P10：生成与写盘流程

1. 捕获当前输入及模板快照，拒绝重复生成。
2. 验证字段和模板契约，包括重复 YAML 键和单文档结构。
3. 解析 YAML 为保留未知字段的结构模型。
4. 定点应用 P06 允许的变更。
5. 验证节点/组名称唯一、provider 引用、规则目标、代理依赖无环、缓存路径唯一。
6. 验证有效字段中无已知待替换占位符；注释中的示例不作为运行字段错误。
7. 序列化为 UTF-8 YAML，重新解析，确认数值类型、字符串内容和结构未变。
8. 原生保存对话框选择目标；已有文件仅覆盖一次明确确认的目标。
9. 在目标目录创建临时文件，写入并刷新，再以文件系统支持的原子替换或重命名完成保存。
10. 成功后显示文件路径及本次检查范围；失败清理自己创建的临时文件，保留原文件。

内置模板不暴露为可覆盖的外部文件。只允许 YAML 输出，拒绝覆盖软件程序及其依赖；用户选择仓库中的 Mihomo/desktop/config.yaml 或 Mihomo/nas/config.yaml 源模板位置时提示另存，避免误写公开模板。覆盖普通输出文件时校验文件是否在确认后被其他进程修改。目标目录不可写、文件被占用或网络共享不支持预期操作时明确报错，不先删除旧文件。

生成不需要管理员权限。软件不尝试给不可写目录提升权限，用户可另选目录。TUN 运行权限属于代理客户端部署问题。

## 12. P11：验证层次和兼容性边界

### 12.1 每次生成执行

输入格式、模板契约、YAML 语法和类型、静态引用、循环、路径冲突、占位字段及输出写入检查。不访问住宅服务器，不下载用户订阅，不调整正在运行的客户端。

### 12.2 开发和发布执行

使用固定版本的 Mihomo 在独立工作目录验证。Windows 输出在 Windows 内核环境测试，NAS 输出在匹配的 Linux/NAS 或容器环境验证，不能让 Windows 的通过结果代替 NAS 平台验收。

如果内核检查会下载资源，明确记录网络前提、访问范围、超时和结果。需要缓存的检查使用隔离目录；测试不得读取或清空真实客户端工作目录。

### 12.3 部署实测

分别执行干净工作目录首次启动与缓存重启；确认订阅、MRS 和 DNS 实际依赖的 GEO 数据。provider 相对路径属于内核工作/HomeDir，而非必然属于输出 YAML 所在目录。[官方 provider 路径说明](https://wiki.metacubex.one/config/proxy-providers/)

确认客户端是否覆盖端口、TUN、DNS 和 secret，并在文档中记录；同名代理组的历史选择可能覆盖首次默认顺序，因此不能保证导入后一定选择列表第一项。

固定入口进行住宅 HTTP 检查、错误住宅凭据失败且不绕过、恢复后成功、入口切换后重新检查、实际出口与业务验证。UDP 单独验证。沿用现有 README 的隔离测试方法。

软件首版不提供“自动联网验证全部链路”按钮，避免把普通 TCP 探测误当完整链路检查。此功能如后续加入，需独立内核、隔离工作目录及明确的测试网络路径设计。

## 13. P12：隐私与错误处理

默认不持久化订阅 URL、住宅账号密码、自动生成的凭据；仅在本次会话和输出 YAML 中使用。目标网络本地 DNS 同样不写入偏好或历史记录，每次由用户填写。用户明确选择的界面语言自动作为非敏感偏好保存；窗口偏好、选用目标及输出目录可由用户选择记住；允许清除这些设置，清除语言偏好后恢复 en-US。偏好写入失败不影响本次切换或生成。软件没有模板来源设置。

导出 YAML 必须含真实凭据才能运行。界面在保存区域用简短提示说明文件含订阅和密码，不增加每次生成的额外审批流程。默认保存到用户文档目录，不默认放入 Git 仓库。

日志只记录错误类别和脱敏信息，不打印 YAML、本地 DNS 地址、完整订阅地址、密码或含凭据的底层异常。软件不发起模板更新请求，不收集遥测或默认上传崩溃报告。

清理临时文件属于尽力清理，不承诺托管内存、操作系统缓存和磁盘中的敏感内容可被绝对擦除。首版不提供“保存密码”功能，避免不必要的凭据存储系统。

| 场景 | 行为 |
| --- | --- |
| 输入缺失或格式错误 | 字段内提示，阻止生成 |
| DNS 环境参数未设置 | 引导填写目标网络 DNS，不猜测 |
| 内置模板缺失、损坏或版本不一致 | 阻止生成，显示软件及模板版本，提示重新下载对应完整软件包 |
| 保存失败 | 原文件保持，提供重试或另存位置 |
| 取消保存 | 不显示成功，不留下新目标文件 |
| 尚未联网测试 | 显示“本地配置检查通过，连接状态未测试” |
| 语言偏好无效或资源条目缺失 | 回退英文（美国），不显示资源键；记录不含输入内容的诊断代码 |

上述提示按当前语言显示，诊断代码在六种语言中保持一致。底层系统异常不直接作为用户提示；先映射为脱敏的本地化说明，必要的技术详情可保留原始术语。

A12–A15 缺少运行环境或有效测试资料时标记“未验证”，不能以单元测试代替。真实资料只在本地私密部署副本使用，不要求用户在对话中公开。

非功能目标：本地生成在约 100KB 模板和六条订阅场景下通常在 1 秒内完成，校验与写盘不阻塞 UI；这是待实测的验收目标，不是当前测量结果。模板解析设定合理大小和深度限制；生成器无模板网络下载任务。

## 15. P14：开发阶段、发布及交付

| 阶段 | 内容 | 交付与完成条件 |
| --- | --- | --- |
| 1 | 建立模板契约、固定基线及开发结构 | 字段映射、模板清单、虚构输入测试夹具；不重新优化模板网络策略 |

| 4 | 目标平台集成验证 | 记录客户端、内核、NAS 部署版本和未通过项 |
| 5 | 打包、文档和发布准备 | 含全部六语资源及指南的自包含 win-x64 ZIP、校验和、变更记录 |

**唯一交付形式为自包含 win-x64 ZIP 便携包。** 用户下载 → 完整解压 → 双击 Skyline.exe → 填写信息并生成。包内包含所需 .NET 运行时和程序依赖，模板嵌入程序，无需单独下载。无需安装向导、MSI/MSIX/Setup 安装包、另装 .NET、管理员权限或代理驱动。

允许 ZIP 中包含 exe、依赖库、许可和使用说明，不强求一个 exe；用户应解压整个包后运行，不只拷贝 exe。发布文件名建议为 Skyline-<软件版本>-win-x64-portable.zip。构建说明使用自包含发布配置，避免误交付需要预装运行时的包。

六种语言共用一个 ZIP，不按语言分发不同安装包或要求另装语言包。若语言资源以程序集和子目录发布，全部纳入 ZIP 并在打包后验证；保持离线可用。翻译修订也随新的软件版本发布。

升级只需下载新版完整 ZIP，解压到新目录后运行，无安装或迁移向导；不自动混合覆盖旧目录的依赖。旧版可保留用于回退。不创建服务、计划任务、自启动项或系统级文件关联。移除软件可删除解压目录；用户主动保存的配置和用户目录中的非敏感偏好独立保留，可在设置中清除偏好。后续可评估 ARM64 和代码签名，安装包不属于本方案规划。

CI 在提交/PR 时构建、测试，核对软件版本、内嵌模板版本与哈希、清单及便携包依赖；版本发布工作流生成待发布 ZIP 和校验和。模板变化时必须更新绑定记录并以新软件版本发布，禁止在同一发行版本替换模板。准备发布不等于自动向 GitHub 公布，实际公开发布按届时指令执行。补充 .gitignore 排除 bin/obj、私密配置和本地测试目录，但不使用覆盖所有 YAML 的规则。

CI 增加翻译资源键、占位参数、必需资源文件和离线指南完整性检查；发现必需翻译缺失时阻止发布，不能把运行时英文回退当作已完成六语支持。布局与译文语义另行人工审阅，自动检查不代替语言质量验收。

交付包含源码、模板契约、统一六语 Windows 包、测试报告、六语用户指南、版本兼容清单和实际未验证项。保留仓库既有 LICENSE，并附第三方依赖许可信息；许可原文不自动翻译替换。

## 16. P15：审阅决策和后续扩展

建议本次一并确认：

1. 使用 Windows 原生 WPF/.NET 10 方案，首版仅提供下载解压即用的自包含 x64 ZIP 便携版。
2. 1–6 条订阅、一组 SOCKS5 住宅代理；不做远程订阅转换。
3. 按最新模板保留入口手动优先、NAS TUN 默认和现有网络策略。
4. 每次手动填写目标网络本地 DNS，不记住、不自动回填或代填。
5. 控制密钥及 NAS 入站用户名/密码放入基础表单，默认自动生成，用户可逐项填写或重新生成；不持久化秘密。
6. 仅使用该软件版本的内置模板，模板更新必须随软件新版本发布；无本地仓库来源或独立 GitHub 模板更新。
7. 首版默认仅作本地检查，内核和真实网络验证纳入开发发布验收。
8. 首版完整支持六种语言，首次启动默认英文（美国），切换无需重启；仅界面与帮助本地化，配置内容不随语言变化。
9. 取消高级设置区域及 TUN、NAS 工作模式、住宅 UDP、住宅认证方式、本地监听端口、NAS 访问管理六类设置；固定继承模板值，住宅用户名和密码仍是必填基础字段。

后续可独立规划：多住宅出口、HTTP/HTTPS 住宅协议、加密本地配置档案、完整链路诊断、NAS 部署助手、其他平台 GUI。它们不阻塞首版核心流程，也不提前加入当前范围。

## 17. P16：多语言与本地化设计

### 17.1 支持范围与默认值

| 语言 | 资源标识 | 菜单显示名称 |
| --- | --- | --- |
| 英文（美国） | en-US | English (United States) |
| 简体中文 | zh-CN | 简体中文 |
| 繁体中文 | zh-TW | 繁體中文 |
| 日文 | ja-JP | 日本語 |
| 德语 | de-DE | Deutsch |
| 法语 | fr-FR | Français |

繁体中文首版采用台湾用语作为翻译基准，德语采用德国、法语采用法国用语。这些地区标识用于统一资源和格式，不限制用户所在地区。所有六种语言都属于首版必交付范围。

无已保存的有效语言偏好时，一律使用 en-US，不按 Windows 显示语言、位置或区域自动选择。用户主动切换后保存语言代码，下次启动恢复；清除偏好或遇到不支持的代码时回到 en-US。语言菜单使用各语言自身名称，不以国旗代替语言名称。

### 17.2 文案与帮助范围

本地化包括窗口标题中的功能文字、菜单、字段标签、占位提示、按钮、工具提示、校验消息、应用自有对话框、成功/失败状态、脱敏变更摘要、NAS 凭据用途说明、导入指引、无障碍名称及离线用户指南。产品名 Skyline Configurator、协议名和字段技术标识如 server、port、DNS 保持稳定，必要时配本地化解释。

Windows 原生保存对话框的系统按钮、系统权限提示及外部客户端界面可能使用操作系统或各自语言。应用控制的对话框标题和文件类型说明使用当前语言，不承诺强制改变操作系统文案。不修改系统语言设置。

生成 YAML 和仓库模板不制作六份语言副本；语言切换也不翻译用户输入、密码、路径、URL、代理组和规则。说明性输出与机器读取配置分开处理。

### 17.3 切换、资源和格式

空闲状态下语言切换立即生效，刷新当前页、校验消息、帮助和结果说明，不重新创建配置或生成密钥。切换语言不视为新建配置，因此不清空本次已填 DNS。正在编辑的输入法组合先完成或提交；写盘及模态操作期间延后切换，操作结束后再刷新，避免丢失输入。

以 en-US 为基准维护稳定资源键、完整句子及格式参数，不用字符串拼接组织不同语言语序。数量变化使用对应语言的句式规则；翻译校验覆盖参数名称与类型，避免显示原始格式占位符。繁体中文须独立审阅术语，不能仅机械简繁转换后认定合格。

采用显式的六语允许列表和 en-US 回退，不依赖系统语言进行隐式选择。缺失单条翻译时回退对应英文；必需语言资源缺失则以英文显示可理解的错误。运行时回退用于容错，正式发布仍要求六语齐全。

界面日期、数量可按所选语言显示；版本号、错误码和技术单位保持清晰稳定。机器读取内容固定使用配置格式要求。字体使用 Windows 可用字体和字体回退，验证无需额外安装字体即可显示中日文字及德法重音；长文案允许换行，键盘快捷键按语言检查冲突。

### 17.4 发布验收

每种语言均执行 Windows/NAS 正常生成、DNS 缺失、非法端口、保存取消/失败、预览和结果页流程。检查译文准确性、术语一致性、文字溢出、输入法、键盘与屏幕阅读标签；对同一固定测试输入比较六语 YAML 输出一致。具体通过标准见 A19–A23。
